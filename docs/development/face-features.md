# 人脸功能对比与递进计划

## 对比依据（2026-10-09）

- [digiKam 官方 People View 文档](https://docs.digikam.org/en/left_sidebar/people_view.html)：扫描范围、重扫／仅识别、Unknown 待命名人脸、手工框选、批量命名、确认／拒绝建议、删除误检。
- [Immich 官方人脸识别文档](https://docs.immich.app/features/facial-recognition/)：检测与人物分组分离、人物命名和搜索、按新的人脸队列识别、模型及距离／最少样本参数。官方也说明，阈值不合适会导致重复人物或错误归组，不能照搬其他模型的数值。

没有使用用户照片进行对比，也没有声称某个识别器对所有人群更准确。

## 本轮已实现

| 能力 | 原状 | 现在 |
| --- | --- | --- |
| 检测范围 | 只有全图库入口 | 当前图片、选中图片（包括 RAW）、全图库，空选择不会误触发全库 |
| 复查 | 重跑流程容易混淆 | 普通检测复用已扫描结果；重检需确认，仅替换所选图片 |
| 多人脸显示 | 只画当前人物，半透明角线 | 显示全部人脸及未命名人脸，完整红框、黑白对比边、稳定颜色徽标、序号／姓名 |
| 标注尺寸 | 缩放和预览尺寸影响辨识 | 预览坐标缩放，屏幕固定 3px 红框，选中人物 4px 加黄色高亮 |
| 结果反馈 | 每十张更新，视图不刷新 | 逐张提交／通知，图片立即刷新检测框；扫描中按小批量分组并更新人物列表 |
| 既有人物 | 每次聚类删掉全部人物 | 已有人物作为固定锚点，保留人物 ID／姓名，只分配未归属人脸 |
| 重检数据安全 | 删掉旧人脸再插入 | 同位置匹配（IoU ≥ 0.5）保留人脸 ID／归属；原始媒体不改写，失败回滚 |
| 解码质量 | 优先小缩略图 | 原图／高分辨率格式预览；先应用 EXIF 方向再检测 |

**边界：** 检测结果逐张保存，人物分组在扫描过程中分批提交，人物列表原位更新，不再等待任务结束。已有人物暂时视为不可重新分配的锚点；更改聚类参数影响待分组的新脸，不会自动拆分已存在的人物。

## 后续优先级

1. **人工纠错闭环（最高）：** 就地改名、单个人脸改归属／创建人物及移除归属已经实现；已补齐确认／拒绝自动建议、标记非人脸或忽略、恢复入口和显式人工确认标志。
2. **人物管理：** 合并重复人物、按人脸子集拆分、批量改归属和未分组入口已实现；封面选择、隐藏／取消隐藏也已补齐。
3. **真正的增量人物识别：** 可恢复的小批量任务、持久进度、扫描中逐步出现人物；软性自动分组与人工固定标签分离，而不是过早冻结错误结果。
4. **漏检与可移植性：** 手工框选补录人脸、多尺度检测、XMP 人脸区域导入／导出，需先设计坐标／方向与人工标注的存储契约。
5. **评估而非宣传：** 对经过授权、带标签的照片集测量漏检、误检、错误合并／拆分与 CPU／GPU 性能。

## 验证重点

SQLite 内存测试检查空／混合／失效选择、缓存复用、原子重检、姓名／人脸 ID 保留、非目标图片不变及 EXIF 方向。前端测试检查单／批处理作用域、图库切换、确认取消、全部人脸显示、预览坐标、固定屏幕线宽及颜色稳定性。真实推理只使用公开的 astronaut 测试图片和校验固定的模型资源。

## 就地编辑人物标签

点击检测框上的姓名／编号按钮，在标签附近打开编辑浮层。已分组的人脸默认“重命名此人物”，明确提示会同步所有照片；识别错的人脸应选择“改归属”，仅改变当前人脸。未分组的人脸可以创建人物或关联已有的人物，不能通过重命名误改其他人物。

同名不会自动合并：改名／新建遇到已有姓名时提示改归属。空白、超长及控制字符姓名被拒绝。人物创建和人脸关联是一个事务；提交时核对图库、模型指纹、人脸所属图片、原人物 ID 和原姓名，拒绝过期编辑。改名／改归属通过事件刷新图片、人物列表和文件信息，缩放及图片快捷键不干扰输入；回车保存、Esc 取消，IME 输入确认不会提前保存。

## 必要短板补齐：第一阶段（已实现）

本阶段不接入年龄／性别等属性模型，也不接入 VLM。首先把人工整理成果从可重建的模型索引中分离：`face_annotations` 保存按原始尺寸归一化的人脸区域、人工人物归属／明确移除归属、源文件版本及时间；`persons.manual` 标记长期保存的人物。

- 切换不兼容模型、修改索引参数、重置自动结果，不删除人工人物或姓名，只清除向量、自动分组和检测缓存。
- 重检遗漏人工区域时保留人工标签；新模型再次检测到该区域后补上新向量。人工区域没有向量时不会伪称为模型识别结果。
- 明确移除归属的人脸不会被下次自动聚类重新分配。
- 源文件大小或修改时间变化，原标注保留待复核，但不自动套到新内容上。
- 旧版本没有人工来源标记，因此一次性保守导入已有姓名的人物与有效区域，优先防止用户整理成果丢失。

第二、三阶段已接入下述复核及人物管理，第四阶段已补齐扫描中的增量人物列表与封面／隐藏。手工补框、持久化可恢复任务等其他功能按当前需求暂缓。


## 必要短板补齐：第二阶段（复核工作区）

人物面板增加“人脸复核”入口，按当前图库显示全部区域，不受选中相册／人物限制：待确认、未归属、已确认、已忽略／非人脸，以及源文件已变化。普通检测／聚类的归属显示为“自动建议”，不会被冒充为人工确认。

- 每页 36 个区域，显示缓存裁剪预览、人物／来源文件与状态。支持选择本页或逐个选择，批量操作前必须确认。
- 自动建议可确认或拒绝；拒绝后保存为人工未归属，不被后续自动聚类覆盖。可通过标签浮层重新指定人物，搜索包括暂无有效人脸的人工人物。
- 可在框上或工作区忽略／标记非人脸。原始媒体不改写，忽略标注跨模型保存，重检会抑制对应区域；“已忽略／非人脸”可恢复至未归属，旧向量和旧人物不会直接复用。
- 源文件变化后的标注只读展示，不将旧区域套在新内容上，亦不允许批量恢复。请重新检测／标注新内容；目前不提供自动迁移旧区域。
- 批处理是单一 SQLite 事务，提交前核对图库、模型指纹和每个区域的完整快照；任一项过期全部回滚。人物删除也采用事务，确保观察记录与长期标注不会只更新一半。
- 裁剪预览仅使用现有缩略图缓存，每页最多 3 个并发请求；无预览时可继续整理，不会为复核自动上传照片或运行模型。

人物合并／批量改归属已在下述第三阶段补齐；手绘区域尚未提供；人物分组现已改为扫描中小批量提交，但任务持久化、暂停／恢复仍未提供。


## 第三阶段：人物合并、批量纠正与拆分

- 人物菜单提供“合并人物”：选择已有目标、获取预览、再次确认。整体转移源人物的观察记录和人工标注，保留目标 ID／姓名及有效封面；源人物记录移除。合并不会重新计算或混用模型向量，源文件已变化的标注仍以原版本保留。
- 预览对源／目标人物的姓名、人工状态、封面、全部观察与标注及源文件版本计算摘要。确认时在单一事务中再次检查；变更、失效区域或数据库错误导致全部回滚。合并没有一键撤销，界面明确提示可通过选择人脸拆分纠正。
- “管理／拆分此人物的人脸”限定到当前人物，混合显示待确认与已确认区域。全局复核也新增“全部有效人脸”。批量改归属只移动所选区域；批量拆分只创建一个新人物，所选区域均保存为该人物的人工确认标注，不影响未选区域或原人物姓名。
- 已有人物选择器支持姓名及 `#人物编号`，可查找首批 50 项之外的未命名人物及暂无有效观察的人工人物。批量指定已有目标时验证其姓名未变化，避免过期选择误写。

### 就地改名不再重载页面

纯改名不发送全图库人脸失效事件。照片标签、人物侧栏、文件信息、复核卡片与当前人物标题原位更新姓名；保留对象／区域 ID、已有裁剪预览和仍在当前分类中的选中项（确认后移出待确认分类的卡片除外），不重查照片列表，不退出临时人物视图，也不重置图片缩放／滚动。人工确认状态不改变成员关系时也不重载照片查询。

真正的归属变更只通知相关图片／人物。后台刷新同一图片的人脸区域时，先保留现有框，等待结果到达再替换；图库、图片或模型上下文变化才立即清空旧框。手绘漏检区域和持久化任务仍未提供；扫描中的小批量人物分组已在下一阶段补齐。


## 误报与认错人物的入口

点击图片标记框上的姓名／编号，在浮层顶部“识别有误？”中选择：

- **认错人：取消归属**：确实是人脸，只移除与当前人物的关联；也可通过“改归属”选择正确人物，不应改名整个旧人物。
- **误报：这不是人脸**：切换至非人脸操作，再点“确认标记误报”才保存。该区域被隐藏，人工非人脸标注在换模型后保留；同一源文件重检时按重合区域过滤。
- **忽略**：真实人脸只是暂时不参与整理，与“非人脸误报”区分。

批量入口是“人物 → 人脸复核 → 标记误报（非人脸）”；恢复入口为“已忽略／误报”。这些操作不删除原图、不删除原人物，也不会训练模型或让模型自动学会避免其他图片中的类似误报。源文件版本改变时旧标注不自动应用到新内容。


## 分阶段检测诊断（不改变阈值）

每次任务完成保存一份当前窗口的诊断报告，可在人物面板重新打开。手动选择图片检测遇到质量过滤、人工屏蔽、无检测结果或失败时自动展示详细报告；全图库任务只提示摘要，不打断浏览。

报告列出模型 ID／版本／索引指纹、实际执行提供者及回退原因、检测输入边长、置信度／清晰度阈值。每张图片显示原文件元数据尺寸与实际读图尺寸、阈值后检测数、质量过滤数、标注屏蔽数和保存区域数；最多保留 100 张逐项详情，每图最多 20 个分数样本，汇总不截断。

置信度取模型全部候选框的最高值，检测数是在阈值筛选及 NMS 后计数；不能把候选框数量当成独立人脸数量。清晰度以四位小数展示（如 199.9379 < 200），图区尺寸帮助识别原图与缩略图测试的差异。读图、输入解码、检测器、对齐／特征提取、源文件校验、输出校验及数据库提交失败独立标记；失败不抹掉旧标注。人工区域也独立计数，避免冒充本次检测结果。

复制功能导出参数、文件名及错误详情，不包含照片、向量或 API 凭据；分享前仍应检查错误文本是否带有本地路径。HEIC 异常解码会影响 AI 输入，报告提示检查预览及缩略图重建。本轮没有更改质量过滤阈值或人脸匹配算法。


## 第四阶段：扫描中分组与人物展示偏好（2026-10-10）

- 第一张保存了区域的图片立即尝试分组，此后每 16 张有区域的图片或距上一批分组约 2 秒触发下一批；时间检查发生在每张图片处理结束时，不会打断单张推理。扫描结束处理剩余区域，未达到模型最少样本要求的区域保留待分组。
- 已归属的人脸继续作为固定锚点：后续批次复用人物 ID／姓名，不自动合并或拆分已出现的人物。每批人物创建与归属写入采用一个事务，失败或提交前取消全部回滚，已完成批次保留。
- 人物面板进度改为非阻挡区域，可边扫描边浏览。批次事件仅带相关人物／图片 ID，列表保留已有行对象、顺序和选择，刷新已加载窗口并按 ID 补取被排序挤出窗口的旧行。相关人物照片查询保留临时人物视图、随机排序种子和选择锚点。
- 人物菜单提供“选择人物封面”，在该人物的复核页选取一张有效人脸。选择封面明确确认这张人脸的人工归属；保存裁剪图及长期标注引用，重检或换模型后恢复封面关联。过期快照、非本人区域、误报／忽略区域不能作为封面；无缓存预览时先重新生成照片缩略图。
- “隐藏人物”只改变人物列表展示偏好，不删除媒体、不修改人脸归属或人工区域。默认人物列表不显示隐藏项；“已隐藏”页提供取消隐藏，即使换模型后暂时没有有效观察的隐藏身份也保留恢复入口。隐藏并不禁止后台识别，也不是照片隐私锁。
- 本阶段没有增加手绘补框、暂停／断点恢复、操作撤销、重新分组工具或年龄／性别属性。
