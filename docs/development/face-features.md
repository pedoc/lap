# 人脸功能对比与递进计划

## 对比依据（2026-10-09）

- [digiKam 官方 People View 文档](https://docs.digikam.org/en/left_sidebar/people_view.html)：扫描范围、重扫／仅识别、Unknown 待命名人脸、手工框选、批量命名、确认／拒绝建议、删除误检。
- [Immich 官方人脸识别文档](https://docs.immich.app/features/facial-recognition/)：检测与人物分组分离、人物命名和搜索、按新的人脸队列识别、模型及距离／最少样本参数。官方也说明，阈值不合适会导致重复人物或错误归组，不能照搬其他模型的数值。

没有使用用户照片进行对比，也没有声称某个识别器对所有人群更准确。

## 本轮已实现

| 能力 | 原状 | 现在 |
| --- | --- | --- |
| 检测范围 | 只有全图库入口 | 当前图片、选中图片（包括 RAW）、全图库，空选择不会误触发全库 |
| 复查 | 重跑流程容易混淆 | 普通检测复用已扫描结果；重检需确认，仅替换所选图片 |
| 多人脸显示 | 只画当前人物，半透明角线 | 显示全部人脸及未命名人脸，完整红框、黑白对比边、稳定颜色徽标、序号／姓名 |
| 标注尺寸 | 缩放和预览尺寸影响辨识 | 预览坐标缩放，屏幕固定 3px 红框，选中人物 4px 加黄色高亮 |
| 结果反馈 | 每十张更新，视图不刷新 | 逐张提交／通知，正在查看的图片立即刷新检测框，收尾聚类后更新名称 |
| 既有人物 | 每次聚类删掉全部人物 | 已有人物作为固定锚点，保留人物 ID／姓名，只分配未归属人脸 |
| 重检数据安全 | 删掉旧人脸再插入 | 同位置匹配（IoU ≥ 0.5）保留人脸 ID／归属；原始媒体不改写，失败回滚 |
| 解码质量 | 优先小缩略图 | 原图／高分辨率格式预览；先应用 EXIF 方向再检测 |

**边界：** 当前增量的是检测结果和计数。人物分组仍在任务收尾阶段运行，并不是人物列表的实时增量聚类。已有人物暂时视为不可重新分配的锚点；更改聚类参数影响待分组的新脸，不会自动拆分已存在的人物。

## 后续优先级

1. **人工纠错闭环（最高）：** 就地改名、单个人脸改归属／创建人物及移除归属已经实现；下一步增加确认／拒绝自动建议、标记非人脸或忽略，以及显式人工确认标志。
2. **人物管理：** 合并重复人物、拆分错误人物、封面选择、隐藏／取消隐藏；显示未分组人脸的独立入口。
3. **真正的增量人物识别：** 可恢复的小批量任务、持久进度、扫描中逐步出现人物；软性自动分组与人工固定标签分离，而不是过早冻结错误结果。
4. **漏检与可移植性：** 手工框选补录人脸、多尺度检测、XMP 人脸区域导入／导出，需先设计坐标／方向与人工标注的存储契约。
5. **评估而非宣传：** 对经过授权、带标签的照片集测量漏检、误检、错误合并／拆分与 CPU／GPU 性能。

## 验证重点

SQLite 内存测试检查空／混合／失效选择、缓存复用、原子重检、姓名／人脸 ID 保留、非目标图片不变及 EXIF 方向。前端测试检查单／批处理作用域、图库切换、确认取消、全部人脸显示、预览坐标、固定屏幕线宽及颜色稳定性。真实推理只使用公开的 astronaut 测试图片和校验固定的模型资源。

## 就地编辑人物标签

点击检测框上的姓名／编号按钮，在标签附近打开编辑浮层。已分组的人脸默认“重命名此人物”，明确提示会同步所有照片；识别错的人脸应选择“改归属”，仅改变当前人脸。未分组的人脸可以创建人物或关联已有的人物，不能通过重命名误改其他人物。

同名不会自动合并：改名／新建遇到已有姓名时提示改归属。空白、超长及控制字符姓名被拒绝。人物创建和人脸关联是一个事务；提交时核对图库、模型指纹、人脸所属图片、原人物 ID 和原姓名，拒绝过期编辑。改名／改归属通过事件刷新图片、人物列表和文件信息，缩放及图片快捷键不干扰输入；回车保存、Esc 取消，IME 输入确认不会提前保存。

## 必要短板补齐：第一阶段（已实现）

本阶段不接入年龄／性别等属性模型，也不接入 VLM。首先把人工整理成果从可重建的模型索引中分离：`face_annotations` 保存按原始尺寸归一化的人脸区域、人工人物归属／明确移除归属、源文件版本及时间；`persons.manual` 标记长期保存的人物。

- 切换不兼容模型、修改索引参数、重置自动结果，不删除人工人物或姓名，只清除向量、自动分组和检测缓存。
- 重检遗漏人工区域时保留人工标签；新模型再次检测到该区域后补上新向量。人工区域没有向量时不会伪称为模型识别结果。
- 明确移除归属的人脸不会被下次自动聚类重新分配。
- 源文件大小或修改时间变化，原标注保留待复核，但不自动套到新内容上。
- 旧版本没有人工来源标记，因此一次性保守导入已有姓名的人物与有效区域，优先防止用户整理成果丢失。

第二阶段已接入下述复核工作区。其后依次实施人物合并及批量改归属／拆分 → 手工补框 → 持久化可恢复任务及实时增量人物列表；这些后续能力尚未实现。


## 必要短板补齐：第二阶段（复核工作区）

人物面板增加“人脸复核”入口，按当前图库显示全部区域，不受选中相册／人物限制：待确认、未归属、已确认、已忽略／非人脸，以及源文件已变化。普通检测／聚类的归属显示为“自动建议”，不会被冒充为人工确认。

- 每页 36 个区域，显示缓存裁剪预览、人物／来源文件与状态。支持选择本页或逐个选择，批量操作前必须确认。
- 自动建议可确认或拒绝；拒绝后保存为人工未归属，不被后续自动聚类覆盖。可通过标签浮层重新指定人物，搜索包括暂无有效人脸的人工人物。
- 可在框上或工作区忽略／标记非人脸。原始媒体不改写，忽略标注跨模型保存，重检会抑制对应区域；“已忽略／非人脸”可恢复至未归属，旧向量和旧人物不会直接复用。
- 源文件变化后的标注只读展示，不将旧区域套在新内容上，亦不允许批量恢复。请重新检测／标注新内容；目前不提供自动迁移旧区域。
- 批处理是单一 SQLite 事务，提交前核对图库、模型指纹和每个区域的完整快照；任一项过期全部回滚。人物删除也采用事务，确保观察记录与长期标注不会只更新一半。
- 裁剪预览仅使用现有缩略图缓存，每页最多 3 个并发请求；无预览时可继续整理，不会为复核自动上传照片或运行模型。

本阶段未提供人物合并／批量改归属、手绘区域，也未改变任务收尾才聚类的机制。不要将检测逐张刷新误称为人物列表实时增量。
