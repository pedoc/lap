# 识别优先排队与跨类型并行验证

日期：2026-10-26。

## 行为与边界

- 语义、人脸、OCR、对象使用独立推理通道。不同类型可同时执行，同类型从图片读取、推理到来源复核和提交保持互斥。
- 手动选图（含重新识别）优先于后台批次；当前照片处理完后让出，同优先级按请求提交顺序处理。手动请求在模型准备、两图之间也保留优先权，完成／取消／异常退出立即释放登记，完成历史不会继续占队列。
- 后台继续时重新检查来源和缓存，跳过已被手动任务处理且仍有效的照片；OCR 的成功空结果仍是有效结果，不重复扫描。对象沿用原任务范围和持久账本，人工修订保留原有保护。
- 每个请求有独立任务 ID、取消和进度；排队回执不会覆盖活动任务。人脸旧任务的完成、聚类或迟到进度不会覆盖新任务。OCR 局部识别与整图识别共用 OCR 通道，局部请求可以独立取消。
- 切库先关闭识别准入并取消旧库所有识别和等待任务，等待当前不可中断处理安全退出；配置及 CUDA 探测仍需要全部通道空闲。
- CUDA 桥保留短会话表锁，执行只锁对应 session；不同 session 可并行，同 session 串行。关闭后旧等待者不能复活会话，首次并发初始化会复核库初始化状态，ABI 保持版本 1。

## 交互与硬件验收限制

实际 Vue 组件的 Node／SSR 回归已验证按钮在同类运行时仍可提交、排队提示、活动进度保留、旧任务事件隔离，以及局部识别等待期间仍可提交整图任务。隔离 Vite fixture 的实际组件和项目 CSS 均通过 HTTP 200 编译预检。

本次未完成浏览器交互和截图验收：CUA 的 Edge／IAB 不可用，ChromeDevTools 无可连接的 DevToolsActivePort；使用独立临时 profile 启动 Edge 的命令被自动审批拒绝，原因是 `blocked by policy`。没有改用其他进程工具绕过；仅清理本任务的 fixture Vite 进程。未生成占位截图，也不将组件测试和编译预检当作原生窗口验收。

没有实测三类真实模型同时运行时的 GPU 吞吐、峰值内存或显存占用；移除全局串行锁不等于硬件一定加速。大图库持续运行及低显存压力仍需实机验收。

后续实机可用合成图库核对：后台对象识别时提交 OCR／人脸应独立启动；同类后台运行时提交选图重识别应优先接续；取消一个请求后其他请求应继续；切库后不应再显示或写入旧库结果。

## 复现

在仓库根目录先运行原生准备；前端命令在 `src-vite` 执行，Rust 命令在 `src-tauri` 执行：

```powershell
node scripts/prepare-native-runtime.mjs
node --experimental-strip-types --test tests/*.test.ts tests/*.test.mjs
pnpm build
cargo check --locked
cargo test --locked -- --test-threads=1
cargo test --manifest-path crates/Cargo.toml --locked -p lap-cuda-bridge -p lap-ai-runtime-wire
```

最后一条 bridge／wire 命令也在仓库根目录运行。运行全量 Rust 测试时将 `LAP_TEST_DATA_DIR` 指向新的绝对临时目录，并清除实际图库／媒体样本环境变量；不要添加 `--ignored`。
