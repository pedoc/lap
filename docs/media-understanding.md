# 媒体理解、Embedding 与自然语言检索

本功能按 **LLM 服务**和 **Embedding 服务**组织用途。LLM 使用 OpenAI 兼容生成接口；文本 Embedding 使用标准 `/embeddings`，也可复用标记兼容的 LLM 服务连接；原画面 Embedding 支持 vLLM 扩展及百炼、方舟、硅基的独立适配器。现有 CLIP 语义检索、人脸、OCR 和对象识别继续使用原有模型与索引。

## 配置 Embedding

1. 点击主窗口左侧的设置按钮，在右侧进入 **AI 模型 → 媒体理解**。
2. 在页签内选择 **Embedding 服务**，直接选中列表中的停用预设或已有服务；自定义端点点 **添加服务**。默认用途旁的 **配置**只定位对应服务／模型，不另开配置向导，不刷新或丢弃当前草稿。
3. 填写服务名称、API 基础地址、API Key 和接口类型。内置条目带入可编辑的示例模型；百炼需要将占位地址改为自己的工作空间地址。**OpenAI 标准文本**用于分析正文和文本查询；多模态协议按实际后端选择 vLLM、百炼、方舟或硅基，均可处理分析文本和原画面。
4. 点 **添加模型**或从“获取模型”列表选择需要的模型，填写服务端 **Model ID**。部署脚本分别提供 `qwen3-embedding-0.6b` 和 `qwen3-vl-embedding-2b`；线上平台使用其实际提供的模型 ID。Mage-VL、Qwen-VL 生成模型不充当向量模型。
5. 选择适合协议的查询编码规则。普通文本不加前缀；Qwen3 文本预设对查询添加 `Instruct: ...\nQuery:...`；vLLM 多模态放在 system 消息中，百炼使用 `parameters.instruct`，方舟使用原生 `instructions`；硅基使用供应商默认规则。模型正文不使用查询指令；方舟另有固定的语料类型指令。
6. 勾选传输许可，点对应能力旁的 **检测**；服务可以保持停用。检测会先保存当前完整配置，再测试接口，检查实际维度、数量、index、有限值及非零向量；多模态检测还发送测试图片。检测成功后显示实测维度，不会自动启用服务。
7. 启用服务，在类别切换按钮旁的“默认用途”栏选择模型，再点 **保存**。LLM 类别显示媒体理解／文本生成；Embedding 类别显示“文本向量”／“原画面向量”，分别对应分析文本和多模态索引。窄窗口会自动换行。检测不自动替换默认模型；配置后也不会自动扫描或上传全库。

基础地址示例：`https://embedding.example.com/v1`。不要填写 `/embeddings` 或 `/chat/completions` 完整路径。基础地址保留网关前缀；非回环地址要求 HTTPS。本机 API 或 SSH 转发可使用 `http://127.0.0.1:8002/v1`。

API Key 存入系统凭据库，不进入 JSON、数据库或备份。留空保留原密钥；移除密钥请用“清除已保存密钥”。修改地址后需要重新输入或显式清除旧密钥。服务名称与部署平台无关。

国内在线服务的可复制参数、模型服务器启动方式和端口转发见 [Embedding 服务使用指南](embedding-services.md)。

已有同时提供标准文本嵌入的 LLM 服务时，可在该服务开启 **兼容 OpenAI 文本 Embeddings**，通过 **手动添加嵌入模型**填写专用 Model ID、检测并绑定“文本向量”。连接和密钥共享，嵌入模型独立于生成模型。关闭兼容标记时保留模型与索引，解除对应默认绑定并禁止调用。完整流程见 [复用 LLM 服务的文本嵌入接口](embedding-services.md#复用-llm-服务的文本嵌入接口)。

## 配置媒体理解和文本生成

在同一个页签选择 **LLM 服务**，直接选择百炼、硅基流动、方舟、DeepSeek 或 LongCat 内置条目，或添加自定义服务。方舟按量、Agent Plan、Coding Plan，以及百炼按量、Coding Plan、Token Plan 个人／团队分别配置，地址相同也不会合并 Token 个人／团队的凭据。预设初始停用、未授权传输、未检测；填入自己的地址与 Key，检测后启用并选择默认用途。获取模型列表或手动添加 Model ID；列表只用于发现模型，不证明模型具备对应能力。

生成模型配置文本、图片、视频采样帧和结构化输出；同一服务兼容文本嵌入时另加独立嵌入模型。专用 Embedding 服务根据服务协议显示文本／多模态检测入口，包含方舟 Agent Plan 原生向量预设。接入方式说明不限制模型可声明的能力；套餐权益适用范围与模型能力分开核对，详见 [接入通道说明](embedding-services.md#接入通道凭据与模型能力)。生成和嵌入用途不能混在同一模型记录中。

“获取模型”后先勾选需要的模型，再点“添加选中”；未勾选的模型不会加入配置。已配置模型标题右侧的移除按钮始终可用，无需展开模型。移除后点击“保存”生效；对应默认用途会解除绑定，已生成的分析和索引保留。再次获取列表不会自动加回已移除模型。

为模型勾选实际能力并分别检测：

交互聊天允许直接使用已启用、已允许传输且已声明相应输入能力的生成模型，不要求先取得逐项检测回执。一次图片／视频检测是否通过，不再决定模型是否出现在聊天列表中；实际请求失败会在会话内显示错误。资料建议、批量理解和 Embedding 仍按原流程检测相应能力。

| 能力 | 实际检测／用途 |
| --- | --- |
| 图片理解 | 上传应用生成的测试图片并校验结构化分析；用于图片资料建议和视觉问答 |
| 视频采样帧 | 上传带时间说明的多张测试图片；用于视频片段采样理解 |
| 文本生成 | 文本请求；用于基于已有分析回答问题 |
| 结构化输出 | 校验标题、说明、标签 JSON；不强制服务实现 JSON Schema 模式 |

勾选能力后，模型立即进入相应用途的候选列表，无需先保存或检测。默认用途分别是媒体理解、文本生成、分析文本 Embedding、原画面 Embedding。候选旁显示未保存、待检测、已检测、服务停用或未允许传输状态。执行任务前仍须检测实际使用的能力，并启用服务及传输许可。“文本生成”默认“与媒体理解相同”，也可独立选择文本模型。一个服务可以有多个模型；LLM 与向量服务可以使用同一服务器地址，也可以完全分开。取消模型所需能力或切换向量协议时，会解除不再适用的默认绑定。

模型配置会按精确 Model ID 显示已核实的公开上下文窗口、最大输入和最大输出，并附官方来源和核实日期。未单列的输入上限保持未知，不用“上下文减最大输出”猜测；动态服务别名和未收录的自定义 ID 也不套用相似名称的参数。供应商只公布 `1024k` 等缩写而未定义精确换算时保留原文。各项上限不保证能同时用满，实际容量还取决于服务、部署和思考模式。规格目录在 `src-vite/src/common/mediaModelSpecs.ts`，仅作参考，不写入模型配置、检测回执或索引身份。

高级选项中的“单次请求输出预算（Token）”是发给服务端的生成预算。新建模型默认留空，省略该参数、使用服务端默认值，不再统一填 2048；已有预算原样保留。已核实数值上限的模型可点“采用官方输出上限”填入预算，也可再次恢复服务端默认值。高于公开上限时会提示，但不会擅自截断网关或自建部署的预算；服务端负责最终校验。修改预算后仍需保存并重新检测。标题、说明和标签的结构化业务字段仍分别校验长度，媒体问答不会再因统一的 64 KiB 回答限制被拒绝。

批量任务还需要勾选服务的批量传输许可。修改地址、密钥、Model ID 或处理参数会使相关检测失效，重新检测后才能调用。更换默认用途不会修改已提交任务的模型快照。

生成模型的高级设置可选择**支持的思考档位**和**默认思考强度**，也可添加兼容服务使用的自定义档位。候选列表不代表所有模型均支持这些值；已核实的精确 Model ID 可点“采用公开档位”，只复制支持列表，公开默认值仅供参考。未知别名请按实际服务说明配置。Embedding 不使用这些字段。

聊天输入区的“模型默认”继承上述设置；“自动”明确省略 `reasoning_effort`，由服务端决定，和显式发送 `none` 不同。其他选择必须在该模型声明的列表内；切换模型时不支持的选择会回到新模型默认，每轮记录实际发送值，不改全局默认。当前统一使用 Chat Completions 的 `reasoning_effort`；服务商独立的思考开关或预算协议不自动转换。例如 DeepSeek 的该参数公开档位为 `low/high/max`，独立的 `thinking.type` 开关不等同于此列表，见[官方说明](https://api-docs.deepseek.com/guides/thinking_mode)。

## Embedding 的服务与模型边界

服务类型决定使用哪一类接口，Embedding 内仍须选择实际提供向量的模型：

| 层次 | 配置内容 |
| --- | --- |
| 服务 | LLM／Embedding 类型、基础地址、API Key、向量接口协议、启用状态与传输许可 |
| 模型 | 对应接口接受的 Model ID、实际检测的维度、模型版本与查询编码规则 |

[OpenAI 官方 Embeddings 接口](https://developers.openai.com/api/reference/resources/embeddings/methods/create/)要求请求包含 `model` 和 `input`，标准 `input` 是文本或 token 序列；返回浮点向量，与聊天接口的文字输出不同。例如：

```http
POST /v1/embeddings
Content-Type: application/json

{"model":"text-embedding-3-small","input":"湖边散步的照片"}
```

因此，服务实现 `/embeddings` 不代表其所有聊天模型都能生成向量。应在 Embedding 服务中添加实际提供的 Embedding Model ID，再检测。只有向量接口的服务也可以单独配置。

“OpenAI 兼容”需要按接口核对。百炼文本与硅基文本复用标准适配器，三家的多模态接口分别编码，并统一校验输出。vLLM 0.14.0 仍使用 `/v1/embeddings` messages 扩展及 `add_generation_prompt: true`。百炼开启 `enable_fusion`，方舟使用其有序输入融合；硅基逐帧编码后本地归一化均值聚合，不把独立批次误当服务端融合。原图／采样帧仅发送本地处理后的 data URL，详细协议对照见 [服务使用指南](embedding-services.md)。

旧版服务配置首次载入时会备份原 JSON 并迁移；同时包含生成和向量模型的服务拆成独立条目。后端维护稳定身份，保留合法检测回执、密钥引用和原有文本索引身份。删除一个拆分条目不会删除其他条目仍引用的密钥。更改协议、模型或查询编码规则后，需要重新检测，并建立对应索引。

## 使用入口

- **图库聊天**：点击图库右下角的聊天浮动按钮，打开可调整大小的会话框；当前多选媒体会作为可附加的媒体传入。首页和隐藏／已删除媒体页不沿用图库列表里残留的选择。
- **悬浮入口设置**：在 **设置 → 通用 → 界面** 中控制是否显示聊天按钮、选择默认四角位置，或重置拖动后的位置。拖动按钮后记忆相对位置；调整窗口大小时保持在可见区域，右下角的任务提示会为按钮留出空间。关闭悬浮入口后，查看器工具栏仍可打开聊天。
- **当前媒体聊天**：点击图片／视频查看工具栏中信息按钮旁的聊天按钮。在对比查看时只引用当前活动一侧，不自动把其他对比媒体一起发送。收起额外工具图标时，聊天入口仍保留。
- **会话与引用**：在输入区旁选择生成模型及思考强度，通过键入 `@` 或拖入媒体明确本轮引用。消息和附件以缩略图摘要卡显示，点击进入现有媒体查看器并显示详情；历史卡片上的小加号才是重新加入本轮。已有回答保留当时的媒体、模型及实际思考强度；Embedding 模型不出现在聊天模型选择器中。
- **会话窗口**：拖动标题栏移动，拖动任意边框或四角调整大小；再次打开恢复位置和尺寸。会话历史保存在当前图库，关闭窗口不中止回答；需要中止时点击“停止”。草稿按会话暂存于当前应用窗口，重启应用后不保留未发送草稿。图库内部拖入只添加引用；外部拖入仅关联已入库的完整路径，未入库媒体需先导入。
- **问答范围**：每轮最多引用 16 项媒体，有附件时直接使用原图／视频采样帧，无附件时进行文字交流。多轮对话沿用历史文字和引用快照；只有本轮附件重新发送画面。聊天选择的模型同时用于该会话发起的资料建议和理解任务，不会更改设置中的默认模型。
- **折叠操作**：输入区的 `＋` 按钮或键入 `/` 打开操作菜单，收纳附件选择、标题／说明／标签建议、选中／全库任务及配置服务。输入 `@` 仍直接打开媒体候选，无需单独的常驻引用按钮。
- **标题／说明／标签**：在聊天中生成资料建议，先预览本轮关联媒体和待写字段，再确认应用。说明写入图库 `comments`；不改文件名、EXIF 或原媒体。信息面板和左侧导航不再放置另一套聊天入口。
- **标签**：默认只匹配已有标签并追加关系。需要新词时显式勾选“允许创建新标签”。忽略的字段按媒体来源版本保留，重新理解同一来源也不会自动恢复。
- **选中／全部媒体任务**：从聊天框 `＋` 操作菜单进入批量面板，选择会话关联媒体或全库可见媒体；多选信息面板和自然语言搜索页不再另放批量理解入口。先预检，明确选择分析、分析文本向量、原画面向量，以及填充空标题／空说明或追加标签。
- **只补建向量**：选择“仅为已有分析补建向量”。不重新解码或上传原媒体，可用于后配 Embedding、切换向量模型，以及重试向量阶段失败。
- **只补建原画面向量**：选择对应任务模式，只需要多模态 Embedding。应用读取原图／采样帧，不调用 LLM，不生成或采用标题、说明和标签；已建好的相同来源、模型与编码版本片段会复用。
- **自然语言检索**：搜索侧栏选择“自然语言”，再选择“分析文本”或“原画面”。前者编码分析描述，后者在多模态模型中将文字查询和原画面向量比较；两类索引不混查。结果进入原有媒体列表，可选择匹配的模型和相册范围。视频匹配保留采样片段时间，可跳转播放。
- **任务**：从聊天框中的任务操作或批量面板查看逐项结果、暂停、继续和重试失败项。关闭面板不停止任务；退出应用后，未完成任务显示为暂停，可显式继续。

仅配置生成模型可以理解媒体、生成资料建议和问答；仅配置多模态 Embedding 可以建立原画面索引并进行文字找图／找视频。分析文本检索需要已有分析和对应文本索引。未配置某类 Embedding 不影响其他链路，之后可以补建对应索引。

## 数据与执行边界

图片按 EXIF 方向解码并缩放至最大 1280 像素；超过 8000 万像素的解码拒绝执行。视频按最长 60 秒分片，每片取 3 张帧，逐片保存；时间标记是请求采样位置，尾部缺少后续帧时仅回退到该采样秒内的可解码画面，不直接使用更早的 seek 关键帧。采样不宣称完整覆盖或精确事件起止；视频最长 24 小时。云端占位原件不会为分析自动下载。

分析 JSON 为 `title`、`description`、`tags`；文档编码为标题、说明、标签三行文本。向量做 L2 归一化，按余弦相似度检索。索引身份包含稳定服务身份、服务地址、远程模型、声明版本、维度、协议和查询编码规则，和 CLIP 索引隔离。原画面向量使用独立的 `media_ai_visual_vectors` 表，并固定预处理／采样规则；不伪造分析记录。相同维度不等于相同向量空间。更换默认模型后应补建对应索引；原索引仍保留，可选择原来的有效模型继续查询。服务端换权重而不改别名无法自动识别，需更新模型版本并重建。

检索首版使用 SQLite 流式精确匹配，内存保留有限候选，不为查询读取原媒体。最多返回 100 个片段，同一媒体保留最佳片段排名；尚未引入大规模 ANN 加速。聊天中的本轮引用决定问答媒体范围；视频回答仅依据提供的采样帧，不代表已经逐帧查看整段视频。

每次写入检查图库、可见性与来源版本；采用建议使用事务并比较原标题、说明和标签快照，避免覆盖并发人工修改。分析、向量、任务和问答存入独立的 `media_ai_` 表，随图库数据库备份；服务配置随应用设置备份，密钥需要在新机器重新输入。

当前接入 Chat Completions、标准文本 Embeddings，以及 vLLM、百炼、方舟和硅基的多模态格式。不含 Responses、Claude Messages，或 Lap 管理的 Mage／Qwen 下载及本机推理环境。自建模型服务可使用 [部署脚本](../scripts/ai-server/README.md)，其中 `embedding-multimodal` 是独立的专用向量模型环境；原 Mage/Qwen-VL profile 仍用于理解和生成。真实供应商账号权限、模型效果、显存需求与检索质量仍需在目标环境验收。

套餐通道和凭据隔离的测试与边界见 [套餐接入验证](development/verification/service-access-variants.md)，基础目录行为见 [内置停用服务目录验证](development/verification/service-presets.md)。共享连接、三家原生协议及原服务拆分记录分别见 [LLM 服务共享文本 Embedding 验证](development/verification/llm-shared-embedding.md)、[国内 Embedding 接入验证](development/verification/embedding-domestic-providers.md)和[服务拆分与原画面向量验证](development/verification/media-ai-services-v2.md)。

会话入口、引用、资料建议及浮动位置设置的验证见 [媒体会话验证](development/verification/media-chat.md)。
