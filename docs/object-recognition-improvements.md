# 对象识别改进任务单

原始照片只读；沿用全局模型和按模型参数，不创建图库模型实例。每阶段验证后独立本地提交，不推送。

- [x] I01：统一语义／人脸／对象的实际推理执行通道，支持公平等待、嵌套调用和等待取消。
- [x] I02：对象任务持久化、原范围恢复、按任务重试失败、清晰的停止与实际设备反馈。
- [x] I03：人工补框、调框、框上就地修改和批量修订。
- [x] I04：新机器结果与人工结果的对照、审核和安全合并。
- [x] I05：可选的重叠切片检测和小目标处理。
- [x] I06：对象索引接入统一搜索，保留命中来源与精确条件语义。
- [x] I07：可选的空闲自动增量处理策略，支持暂停与资源让出。
- [ ] I08：原生窗口交互和大图库长期压测；不将构建／组件渲染测试当作实机验收。

当前阶段：I01–I07。后续各项在本阶段稳定后递进，不能将尚未实施项标记为完成。

## 第一阶段实现边界

- 统一推理通道采用 FIFO 等待，等待期间每 50ms 检查任务取消；同一工作线程的内部嵌套调用可重入，租约禁止跨线程转移。语义、人脸、OCR、对象的实际执行受共同约束，批处理按照片让出；模型初始化也受保护。这是保守单通道，不宣称是多 GPU 并行调度或显存预算器。
- 对象任务保存原范围、模型版本／参数快照和照片清单。选中任务在异步准备前即保存路径、修改时间、大小、方向的元数据摘要；清单生成后恢复只使用剩余原照片。未生成清单的文件夹任务沿原范围重新准备，文件夹身份变化会拒绝恢复，不回退整库。
- 单图识别结果与任务项完成标记同事务提交；进度 JSON 即使在崩溃前未刷新，恢复统计也以逐项账本为准。接续任务复制剩余项及源摘要同事务落盘，二次崩溃也不会把范围扩回原整批。失败重试和未完成恢复互不消耗对方的清单。
- 不自动执行历史任务或切换全局模型。模型或索引参数不匹配时禁止恢复；原参数供查看，用户可切回原配置或另建新任务。显示最近 20 条记录，旧记录不会因此自动删除。
- 文件隐藏、删除、源改变、ID 复用均不会重放为其他照片。旧任务若缺少源快照会明确拒绝恢复，不伪造身份。取消等待可及时退出；已进入单张解码／模型执行时仍需等当前操作结束，未声称实现 ORT 内部强制终止。
- 对象页直接展示最近实际推理后端和回退原因；完成的历史任务不会在每次启动时重新弹出完成浮层，中断任务可以提示恢复。

## 第二阶段（I03）实现边界

- 人工修订改为完整文档保存：前端在图片上直接补框、拖动、拖角调整、就地改类与删除，支持 Ctrl／Shift 多选后的批量改类、确认与删除；后端按整份 `ObjectDocument` 校验并落库，不再要求修订数与机器检测数一一对应。
- 修订保存仍然要求 `revision + sourceKey` 一致，模型或照片变化后拒绝写入；框坐标裁剪到 `[0,1]`，改类后清空原机器分数，人工补框标记为已复核。原始照片只读，修订仅写入本地索引与计数。
- 交互坐标系复用图片变换层（平移／缩放／旋转），以 SVG 的屏幕矩阵反算归一化坐标；仅支持有限拖拽交互，不宣称触控或超高 DPI 下的像素级精度。

## 第三阶段（I04）实现边界

- 审核视图对比「当前人工文档」与「最新机器文档」，以 IoU≥0.5 判定同框；已匹配对象继续保留人工类别与复核状态，仅未匹配的机器框列为候选。
- 候选在侧栏勾选后并入人工文档并整体保存；并入的对象保留机器分数并标记已复核，使用新生成的唯一 ID 避免与原框冲突。未勾选候选不写入，人工独有框保持不变。
- 合并仍复用 `revision + sourceKey` 校验和整份文档校验，模型或照片变化时拒绝写入；不自动删除任何人工框，不宣称跨照片批量合并。

## 第四阶段（I05）实现边界

- 新增按模型参数：`object_tiled`（是否启用）、`object_tile_size`（切片边长）、`object_tile_overlap`（重叠比例）。这些参数计入索引身份，切换后需重新识别；设置页由参数 schema 自动渲染。
- 启用后仅当图片任一边大于切片边长时切分，网格带重叠且末块贴边；每块独立预处理与推理，候选框换算回全图归一化坐标后做一次跨类 NMS。未启用时路径与原先完全一致。
- 切片检测通过放大局部区域改善小目标召回，但计算量与切片数成正比；不宣称小目标召回率有保证，也不做逐类先验或像素级小目标专用分支。

## 第五阶段（I06）实现边界

- 统一搜索新增「对象匹配」分组：前端把查询词按本地化名称、模型类别名或类别键解析为当前检测模型的一组类别键，后端以独立 `object_classes` 参数查询，与文件名／备注／OCR 文本查询、视觉语义查询互不污染。
- 对象条件沿用 `count_condition` 的正向语义：以有效行（人工修订优先于机器结果）和 `n >= min` 判定，失败结果不参与；OR 多个类别键时保持逐类参数与精确数量语义。
- 分组按「文本 → 对象 → 视觉」去重，命中来源在分组层面可见；不宣称跨模型语义合并，也不把对象命中冒充为文件名或 OCR 命中。

## 第六阶段（I07）实现边界

- 对象页新增可选空闲策略：默认关闭，可设置空闲秒数、每批照片数和文件夹范围。仅当策略启用、未暂停、图库已建立对象索引、全局模型已安装且没有运行中任务时才启动，单批结束后重新回到空闲等待。
- 任意窗口的交互活动都会延后自动任务；手动启动、重试或恢复任务时自动任务让出。手动停止自动任务会暂停策略，模型缺失或致命错误也会暂停并显示原因，不会自动重试失败照片。
- 自动任务只处理尚未完成的照片，沿用当前全局模型与参数快照，不下载模型、不切换模型、不绕过手动任务的范围与修订保护。轮询与启动仍受统一推理通道约束。

I08 仍待后续阶段。原生窗口交互和大图库长期性能必须单独验收。
